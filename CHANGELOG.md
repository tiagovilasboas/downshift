## [Unreleased]

## [0.9.1] - 2026-11-06

### Fixed

- Release signing now uses a cosign bundle (`checksums.txt.sigstore.json`), because cosign v3 refused the detached `.sig`/`.pem` flags and the v0.9.0 release never published. Release notes: [docs/releases/v0.9.1.md](docs/releases/v0.9.1.md).

### Security

- Claude Code: in `bypassPermissions` or `dontAsk` mode Claude Code runs a shell call without asking, so its deny rules are the only guard. A rule Downshift cannot read (`--disallowedTools`, Agent SDK `disallowedTools`, `--settings <file>`, server-managed policy, MDM) did not match the wrapped command, and a denied command such as `gh pr merge` could run. In those modes, and in any mode Downshift does not know, the shell rewrite is now limited to one read-only command (`git status`, `gh pr view` and the like); everything else runs as typed and meets Claude Code's rules unchanged.
- Background and never-ending commands: the compactor shows output only when the command exits, so a background call or a follow, watch or server command showed nothing while it ran and lost its output if killed. A Bash call with `run_in_background` set is no longer wrapped, and these forms are left as typed: `docker logs -f`, `kubectl logs -f`, `journalctl -f`, `aws logs tail --follow`, `logcli query --tail`, `jest --watch`/`--watchAll`, `vitest watch`/`dev`/`--watch`, `tsc --watch`, `vite preview` and `flutter run`. Their one-shot forms are still compacted.

## [0.9.0] - 2026-11-06

First public beta, tagged but not published (its release job failed at signing). The repository starts a fresh history at this release. The notes live in [docs/releases/v0.9.1.md](docs/releases/v0.9.1.md).

### Security

- Compact refused nothing on `cargo clippy`, so `cargo clippy --fix` (which writes source files) was wrapped. `--fix`, `--allow-dirty`, `--allow-staged` and `--allow-no-vcs` now keep it unwrapped.
- Release pipeline: GoReleaser now creates a draft. `verify-release` downloads every asset on Linux, macOS and Windows runners, checks sha256 against `checksums.txt` and asserts `downshift version` shows the tag; only then `publish-release` publishes. `checksums.txt` is signed keyless with cosign (a `checksums.txt.sigstore.json` bundle) and an SPDX SBOM is attached, next to the existing build-provenance attestation. Verification: [install guide](docs/guides/install.md#verify-a-release).
- Codex: a shell rewrite also approves the command, so Codex never asked. Now Codex rewrites only one read-only command (`git status`, `git log`, `gh pr view`, `go version`, `ls` and the like, with no shell metacharacter, no `NAME=value` prefix and no flag that writes or runs a program). Chains such as `go version ; perl x.pl`, runners such as `make` or `go test`, and mutating subcommands pass through untouched, and Codex asks as usual (`RewriteImpliesApproval`).
- Cursor: the `beforeShellExecution` hook answered `allow` to every shell command, including ones Downshift did not touch, which could switch off Cursor's own approval. It now answers the neutral `{}` (or an `agent_message` with no permission). Cursor's rules cannot be read, so its `Shell` rewrite is limited to the same read-only set (`UnknownUserRules`).
- Compressor learning stored the first three words of a command, which could hold paths, tokens or branch names. It now stores the command's base name and, only for a command that takes subcommands, one subcommand word in a fixed lowercase shape. An existing store is cleaned the next time it loads.
- Worker `diff`: an untracked file named like a git option (`--output=…`) was parsed as one, symlinks were followed, and the worktree's git config could run a program (`core.fsmonitor`, `diff.external`, textconv) on the host. Paths now follow `--`, only regular files are read, and those programs are off.
- Claude Desktop: setup writes `DOWNSHIFT_WORKERS=off` into its MCP entry, because Chat starts the server from `/`. Rerun `downshift setup` to update an existing entry.

### Added

- `ShellDialect` harness capability (A6): the compound (`cmd | tail -N`, `cd d && cmd`) and chain (`a && b`, `a ; b`) rewrites now run only for a harness that declares a POSIX shell (Claude Code, Cursor, Codex, Antigravity, OpenCode). A harness with no declared dialect keeps those shapes unwrapped; one plain command is wrapped as before.
- Codex read-only evidence and event fixture (D5/S2): one real `codex exec --sandbox read-only` run on codex-cli 0.163.0 refused a write and left the directory empty; its JSONL events are a test fixture for `codexSession` and `codexTokens` (`docs/evidence/mcp-codex-2026-11-06.md`).
- `glab` read-only family (F2): `glab mr list|view|diff`, `glab issue list|view`, `glab ci status|list` and `glab pipeline list` are wrapped and their output has GitLab tokens, `PRIVATE-TOKEN` and `Bearer` values and URL credentials shown as `[redacted]`; nothing else is cut, since the output formats are undocumented (corpus fixtures are synthetic). `-w`/`--web`, `--show-token`, `--live` and every other subcommand stay unwrapped, and the raw output is never stored in CCR. The bench baseline gains a `glab` row (new family, no existing row changed).
- Antigravity shell rewrite (F3): a `run_command` call is answered `allow` plus `overwrite.CommandLine` so one read-only command (`git status`, `ls` and the like) runs through `downshift compact`; setup adds the `run_command` hook entry. Documented by the vendor hooks page, not live-verified.
- Main-session work log: a Read result now records its byte count (`result_bytes`) and size class (`result_bytes_bucket`: `<1K`, `1-4K`, `4-20K`, `20-100K`, `>100K`; never content or path), and `downshift report` shows the share of Read results and bytes per class (Claude Code), to measure how much Read output sits above 20 KB before shortening any (#892).
- RuboCop compressor (F2): `rubocop` offences are grouped by file and by cop with counts, every error and fatal offence is kept whole, the summary line is kept as written and a clean run is cut to that line. `-a`, `-A`, `--auto-correct*`, `-o` and a non-default `--format` stay unwrapped.
- `curl` and `wget -O -` caps (F1): a response of 2 KiB or more keeps the status line, key headers and the ends of the body. Only read-style forms are wrapped (no output file, upload, form, header, credential or config option, no method but GET or HEAD, no credentials in the URL), credential-looking response headers such as `Set-Cookie` and `Authorization` are shown as `[redacted]`, and the raw response is never stored in CCR, not even for a failed run. The bench baseline gains an `http_fetch` row (new family, no existing row changed).
- Log repeat dedup (F1): `cat`/`tail` of a `.log` file of 40+ lines collapses runs of lines that differ only in timestamps and numbers, with a count. A run of similar lines that holds a danger word is kept whole.
- JSON schema view (F1): `cat x.json` and `jq . FILE` of a JSON document of 4 KiB or more print its schema (keys, types, array lengths, the shape of the first element; never values). A cut document, several documents and invalid JSON stay raw.
- `downshift discover` and the exec skip log split the `metachar` skip into kinds (`heredoc`, `subst`, `redirect`, `or_list`, `background`, `pipe_grep`, `pipe_other`, `quote`, `glob`, `other`), so the shapes worth supporting can be counted before the grammar widens. `skips_by_kind` joins the exec metrics; the reason stays `metachar`.
- CCR on failure: when `downshift compact` compacts a command that exited non-zero, the raw output is now kept by default and the marker names the id for `downshift retrieve <id>` (and the MCP `retrieve` tool). Successes are stored only with full CCR. Turn it off with `"ccr_failures": false` or `DOWNSHIFT_CCR_FAILURES=0`. See [ccr.md](docs/guides/ccr.md).
- `downshift report --daily` (one row per day of the `--days` window) and `--history` (the whole retained history by week, or `--by=day`): per harness, the tokens the Compactor kept out of the context and the billable tokens that ran below the session model, with `--json`. Tokens only; the default report is unchanged.
- Per-worker reports: `status` lists a report for every worker that ended, released ones too (wave, state, result bytes, tokens, whether its session transcript is still on disk, and `unmarked`, `used` or `discarded`). `release` takes `mark` to record the verdict. A report holds sizes and flags only, never task text, result text or a path.
- Token budgets for delegated workers: `delegate` takes `budget_tokens` for its wave (once spent, `send` and `steer` refuse for that wave's workers and `collect` marks it `over_budget`), and `orchestration.budget_tokens` (env `DOWNSHIFT_BUDGET_TOKENS`) caps the whole session: past it `delegate` refuses with code `budget`. A worker that reported no usage never counts.
- `downshift discover` scans Claude Code transcripts and Codex sessions in memory for shell commands the compactor would have changed but that ran bare, and reports commands seen, already compacted, compactible but bare (with result bytes), skipped by reason, and the top missed command groups. It prints families, program names, counts and sizes only, never arguments or paths (`--since`, `--harness`, `--top`, `--json`).
- Four worker playbooks (`scout-then-build`, `cascade`, `audit-at-scale`, `best-of-n`) and a quota stop line for `delegate`: it refuses with code `quota` when a provider is rate limited or at or past `orchestration.quota_stop_pct` (default 90, env `DOWNSHIFT_QUOTA_STOP_PCT`). The `strain` code is gone: a rate limited provider now refuses the whole call instead of halving it.
- Compact reads files: `cat FILE`, `head`/`tail -n N FILE`, `sed -n 'A,Bp' FILE` and `wc -l FILE...` (one regular file, no other option; `tail -f`, `sed -i`, devices and secret-looking names are refused or left raw). A source or Markdown file of 300+ lines folds to its outline (first and last lines, every declaration and danger-word line, with file line numbers) and a note gives the exact `sed -n` range or the CCR id for the whole text.
- Compact groups wider searches: `rg` and `grep -r` without `-n`, `-l` (paths) and `-c` (counts per file). Grouped rows are capped at 20 per file and 200 in all, with the cut counted. `make bench-baseline` was regenerated for the new `file_read`, `grep_rows` and `grep_counts` rows (they pull the lossless aggregate from 65.8% to 64.2% because `grep_rows` saves 32%; the total rises from 48.1% to 50.8%).
- Compact wraps commands with quoted words: single quotes, and double quotes with no `$`, backtick, `\` or `!`. An exact trailing ` 2>/dev/null` or ` || true` becomes the new `--discard-stderr` or `--exit-zero` flag, and a note at the end of a compacted output says so (uncompacted output is left byte-identical). Every word is single-quoted again in the rewrite; any other metacharacter is still refused, and so are quotes inside a chain and the two forms zsh reads differently (an unquoted word starting with `=`, two touching single-quoted pieces). The Codex and Cursor read-only path is unchanged; user deny and ask rules are matched on the command as typed and on its unquoted words, and while any of them holds a quote the quoted path is off (skip `quoted_rule`). Threat note: `docs/design/compactor-default-on-adr.md`.
- Eight more families compact: `rspec`, `dotnet test`, `phpstan`, `docker build`, `docker ps`, `docker images`, `kubectl get` (pod table) and `git stash list`. Their compressors were present but unreachable. Each keeps the output raw on any line it does not recognise, and writing forms (`docker build --push`, `kubectl get -w`, `phpstan --fix` and others) are refused.
- `downshift doctor` checks that the binary, the Claude Code plugin and the OpenCode bridge are the same version, and warns when the first `downshift` on PATH is not the newest copy. `doctor --check-latest` also compares with the latest release (one GitHub request, 2 s timeout, cached 24 h; offline reads as unknown). Without the flag doctor makes no network call.
- Exec events carry a `passthrough_detail` code (`danger_word`, `ansi`, `cr`, `no_final_newline`, `unknown_shape`, `no_compressor`, `compressor_panic`) and skip rows carry the metacharacter class and family that stopped the rewrite. The report lists both. Only codes are stored, never command text or output.
- A routing `fail_open` names the payload field that failed validation (the name only, never the value). `doctor` says since when each open circuit has been open, the error and field, and whether it is half-open.

### Fixed

- Worker (Codex, write mode): the launch argv used `codex exec -a never`, which codex-cli 0.163.0 rejects (`-a` exists only on the top-level `codex`). It now passes `-c approval_policy="never"`, as the resume path already did. A test checks every flag the recipes emit against `codex exec --help` when `codex` is installed.
- Setup: when Claude Desktop is running, setup no longer writes its `claude_desktop_config.json` (the app drops the entry within minutes); it reports the MCP entry as held, says to quit Claude fully (Cmd+Q) and rerun setup, and exits 0. `--dry-run` shows the same. Where running cannot be detected, setup writes and notes as before.
- Setup: a linked file (for example `~/.gemini/AGENTS.md` into a dotfiles repository) now skips only that file, with one line that names it and says how to fix it. Before, it held back the whole harness, including its MCP registration. The skip is no longer an exit-1 failure. Setup still never writes through a link.
- Setup: the "did not exist" undo marker, and the backup of a file inside a plugin, skill or mod folder, now live in `~/.downshift/backups/<stamp>/` (the path below your home folder is mirrored) instead of beside the file, so harness plugin folders no longer hold zero-byte `.downshift-bak-*.new` files. `--undo` and the backup pruning read both the new place and the old files beside the target. Other backups (`settings.json` and the like) stay beside the file.
- Setup: the lines that report a write now name the file (`opencode: ~/.config/opencode/plugins/downshift/index.ts written (new file).`), so a dry run's file list can be checked against what the real run wrote.
- `downshift doctor` checked the MCP registration for Claude Code only. It now checks every target `setup` registers it for (read from the same target table, config read only, no server started): registered, missing (fix `downshift setup <target>`), or skipped when the harness is not installed.
- `downshift cursor-touch` now goes through the hook read guards (1 MiB cap, read timeout) and recovers from a panic, so it always exits 0 with `{}`.
- Compressor learning lost counts when two compactions ran at once: `Record` read and rewrote its store with no cross-process lock. It now holds a lock file beside the store and, if it cannot get it within 200 ms, skips that observation instead of delaying the command.
- `exec-events.jsonl` and `exec-skips.jsonl` grew without bound. Past 10 MiB the file now moves to `.1` (one generation kept) before the next append, and every reader (`report`, `session`, the context summary) sums `.1` with the current file, so totals do not drop at a rotation. `report clear` also moves `exec-skips.jsonl` and the `.1` files. `context-compactions.jsonl` already prunes itself (90 days, newest 5000 rows) and is unchanged.
- State in `~/.harness-downshift` was orphaned once an empty `~/.downshift` existed (the installer suggests `mkdir ~/.downshift`). `downshift setup` now moves the legacy files in when the new directory is absent or empty, leaves a `MOVED.txt` note, and reports it (`--dry-run` lists what would move). A non-empty `~/.downshift` is never touched: setup names both directories instead. Hooks never move files.
- `downshift doctor` on Windows reports a stale hook binary. A `C:\...` path has no `/`, so it was resolved through PATH and always read as current.
- A clean push keeps a hook box line that carries a warning or a danger word.
- `downshift version` reports the module version for a `go install` build instead of `dev`.
- Failures from a `dev` build older than a day no longer hold a routing circuit open.
- A clean `git commit` that ran hooks is compacted like `git push`: the hook runner's banner boxes, step lines and rules are cut, and the commit line, the hook summary and any failure are kept. Before, only a go test run inside the hooks folded, so a commit with lefthook output stayed raw (`unrecognized_output`).

### Removed

- `internal/orchestration`: about 2,600 lines with no importer.
- Dead routing seams no production path called: `core.TierFloorHook` and its `policyfile` init registration, `core.MemoryAdjustHook`, `core.Check` with `Decision.RaiseTier`, and `policy.ApplyFloor`. The floor tests now run the production decider. The R-rule ids stay as telemetry reason codes.

## [0.8.1] - 2026-11-05

### Security

- `send` and `steer` now pass the same limits as `delegate`. A follow-up turn on a finished worker waits for a free slot instead of starting past the concurrency limit, it is refused once the CLI's token budget (`DOWNSHIFT_WORKER_TOKEN_BUDGET`) is spent, and a session runs at most 4 follow-up turns per allowed worker (128 by default). Before, a looping orchestrator could run every finished worker at once, for any number of turns, past the budget. A timed-out turn's late exit also no longer settles the follow-up turn that resumed after it.
- Claude workers start with `--setting-sources user`, so a `.claude/settings.json` in the directory a worker runs in (a repository, or a dependency folder it was pointed at) no longer runs hooks, sets env such as `ANTHROPIC_BASE_URL`, or widens permissions. In print mode Claude skips the trust dialog, so those files used to load unasked. A read worker also gets only `--tools Read,Grep,Glob` with `--permission-prompts none`. Checked on Claude Code 2.1.318: a project `SessionStart` hook ran under the old flags and not under the new ones.
- Workers inherit a filtered environment instead of the whole parent environment: what the CLI needs passes, unrelated tokens (GitHub, npm, cloud, database) stay out. New variable `DOWNSHIFT_WORKER_ENV` names extra variables to pass, for example a Codex provider key.
- A worker-mode policy file that exists but cannot be used (a symlink, over the size limit, invalid JSON or an invalid value) now sets workers to `off` with a note in `downshift doctor`. Before, such a file was skipped silently and workers fell back to the default `read`, so a user's `"off"` in a symlinked or malformed file was ignored.
- Under a broad MCP server root (the filesystem root, your home or an ancestor of it), a read worker's `dir` is refused when it is broad itself or sits below a hidden (dot) directory such as `~/.aws` or `~/.ssh`. Before, a read worker could be pointed at any directory inside the broad root. The rule covers the worker's working directory, not every file its CLI can read.
- The MCP tool annotations now say which tools act: `delegate`, `send` and `steer` are destructive and open-world, `cancel` and `release` are destructive. Before, every tool claimed to be non-destructive and closed-world, which let a client auto-approve starting a worker.
- The OpenCode bridge checks `DOWNSHIFT_BIN`: when set it must be an absolute path to an existing file, or the bridge stays off. When it is unset, the bridge resolves `downshift` from PATH once at startup (skipping relative entries and files without an execute bit), pins it and runs it; if none is found the bridge stays off. A shell rewrite is applied only when it is the original command with Downshift's wrapper added in command position (at the start, or after `;`, `&&`, `||` or `|`, optionally after `NAME=value` words), only runs of ASCII spaces differ, the original has no quote, `$`, backtick, backslash or control character, and every wrapper names the pinned binary. Any other answer leaves the command unchanged.
- The OpenCode shell guard reads more of the config sources OpenCode reads: `OPENCODE_CONFIG`, `OPENCODE_CONFIG_DIR`, `OPENCODE_CONFIG_CONTENT`, the managed config directory and the macOS managed profile, and `opencode.json(c)` and `.opencode` folders in every ancestor of both the shell's and the session's directory, with agent and mode files that declare `permission` in their frontmatter. A permission rule in any of them keeps the compactor off, and so does any doubt: an unknown or relative directory, a linked agent or mode folder, a config file over 1 MiB or not a regular file, or a frontmatter the scan cannot read. Before, only the project and global `opencode.json` were read.
- `downshift setup` and `setup --undo` refuse a harness file that is a link, or sits under a linked directory (for example `~/.config/opencode` linked into a dotfiles repository), and leave it alone. Windows junctions count. Since 0.8.0 setup resolved the link and wrote into its target; undo also restored and removed files through links and unlinked a linked folder. When one file of a harness is refused, setup changes nothing else of that harness, MCP registration included. Project and state directories outside the home are checked the same way.

### Fixed

- A resumed Codex worker turn keeps its report file (`-o`), so `send` and `steer` on a Codex worker return the turn's final message instead of the raw JSON event stream.
- The OpenCode bridge drops a pending shell session tag after 30 s, so a shell call denied or failed before the shell existed no longer tags a later identical command forever. Parallel shell calls of one session keep their tags. Within the 30 s, another session's identical command can still take the tag (telemetry only). A shell call also waits at most 2 s for the hook, matching the Go read deadline (was 3 s). At most 500 pending tags are held in total, oldest dropped first.
- The OpenCode bridge validates a retry call like a route or shell call (wire version, harness id, event, child id, provider and model caps) and retries only on attempt 2, the first retry opportunity. Before, an absent or first attempt also undid the route.
- The OpenCode bridge keeps a session model whose id contains a slash (for example `deepseek/deepseek-v4.1-flash` listed as `openrouter/deepseek/deepseek-v4.1-flash`). The match dropped everything up to the last slash, so such a model was never routed.
- `downshift setup` on a commented `opencode.jsonc` (or any harness JSON file that is not strict JSON) now prints the MCP entry to add by hand and why the file was left untouched, instead of a bare "not a valid JSON object".
- On Windows a worker starts suspended, joins its Job Object, and only then runs. Before, it joined the job after it had started, so a program it spawned in that window was outside the job and was stopped only by the `taskkill /T` fallback.
- The OpenCode bridge plugin is split into modules (`models.ts`, `shell_sessions.ts`, `shell_trust.ts`, `wire.ts`) that `downshift setup opencode` installs next to `index.ts` in the same plugin folder; run it again after upgrading. `downshift doctor` reports one bridge row for the folder.

## [0.8.0] - 2026-11-05

### Added

The comparison now counts billable tokens (input, output and cache write): the table column is `billable/completed`, `--json` adds `billable_tokens_per_completed_task` and a `basis` field in `tokens_interval`, and `tokens_per_completed_task` keeps the total with cache reads for reference. The report also prints the effect: the share of the routed group's billable tokens that ran on a lower tier than requested (`effect` in `--json`).

### Security

- The compact wrapper's `psql`, `gcloud` and `ast-grep` families accept only the read shapes they can prove, like `mysql` and `redis-cli`. `psql` was wrapped for any use, writes included; it now takes exactly one plain read statement (`-c`) or `-l`/`--version`, with a closed flag list, no `-f`/`-o`/`-L`/`-v`, no connection string and no leading `NAME=value` assignment. `gcloud` was wrapped when `config`, `auth`, `list`, `get` and the like appeared anywhere in the line (`gcloud auth revoke`, `gcloud config set`, `gcloud compute ssh vm --command=...`); the first verb of the command path must now be a read verb, and `--command` refuses. `ast-grep` and `sg` refuse `-U`/`--update-all`, `-i`/`--interactive` and `-c` (the Linux `sg` runs a program under another group). A raw segment of a `;`/`&&` chain that names an infrastructure, cloud or remote-shell program (`kubectl`, `terraform`, `helm`, `aws`, `docker`, `ssh`, `curl`, `dd`, `chmod` and similar) is no longer carried into the rewritten line. Tests: `internal/execwrap/policy_guard_cloud_test.go`.
- The redis-cli and valkey-cli guard accepts only a closed list of flags. A flag it did not know left its value to be read as the command, so `redis-cli -i get flushall`, `-s`, `-d`, `--sni` or `--cacert get flushall` were wrapped as a read, and `--eval get` and `--rdb get` ran a script or wrote a file; any other flag, or a value flag with no value, is now refused. `mysql`, `redis-cli` and `valkey-cli` are never wrapped behind a leading `NAME=value` assignment, because `HOME`, `MYSQL_HOME`, `MYSQL_TEST_LOGIN_FILE` and `REDISCLI_*` can point the client at an option file or another server. Tests: `internal/execwrap/policy_guard_db_test.go`.
- Guarded commands (a recursive `rm`, `mysql`, a `redis-cli`/`valkey-cli` write) are no longer wrapped behind a runner: `direnv exec` and `lerna exec` are named by their inner command, `uv`/`poetry`/`pdm run` refuse a command line that names a guarded program, and `adb shell` leaves the allowlist. A `;`/`&&` chain whose raw segment names a guarded program (also as `sudo rm`, `/bin/rm`, `FOO=1 rm`) is not rewritten (reason `guarded_segment`); on Codex the rewrite is pre-approved, so the raw segment rode along. Tests: `internal/execwrap/policy_guard_runner_test.go`.
- The `downshift export` sensor checks every key against the schema of the export, derived from its struct, not only string values: a map keyed by a repo, a model or a host is refused even with numeric values, `generated_at` must be an RFC3339 timestamp at the root, and `note` and `harness` accept only their own values. A struct field that is a map, an interface or a string without a rule fails the schema test. A harness name outside the adapter table is folded into `unknown`, so an old log no longer makes the export refuse to print.
- The compact wrapper's own guards cover more spellings (the entries below close the gaps a final review found). A recursive `rm` was refused only as `-rf`, `-fr` or `--recursive`, so `rm -r -f`, `rm -R`, `rm -Rf`, `rm -rfv` and the GNU prefix `rm --rec` were wrapped; now any short-option cluster with `r` or `R` and any prefix of `--recursive` is refused. The `mysql-query` family checked only the first word of the first `-e`, so the direct `downshift compact --` call (whose argv comes from the caller's shell, past the hook's safe-byte gate) also accepted `-e "select 1; drop table t"`, a second `-e`, `--init-command`, `--plugin-dir`/`--default-auth`, `--defaults-file`, `--tee`, `--pager`, `INTO OUTFILE`/`DUMPFILE`, `EXPLAIN ANALYZE` and a new line or `\!` client command; it now takes exactly one plain read statement with connection and output options only, and refuses everything else. `redis-cli --pipe`, which sends whatever stdin holds, is refused whatever the keyword. A refused command still runs without the wrapper, so a false refusal only means one unwrapped run; the hook leaves such a command unrewritten. Adversarial tests: `internal/execwrap/policy_guard_test.go`. The filesystem families move to `internal/execwrap/policy_filesystem.go`.

## [0.4.0] - 2026-10-31

### Added

- New MCP tool `release`: it lets go of workers that have finished and deletes the on-disk session transcript each one left behind (fifth piece of worker continuation, task T5 of the worker-continuation plan in the internal plans directory), so a resumable session no longer lingers in the user's resume list once the orchestrator is done with it. It takes the ids `collect`, `cancel`, `diff` and `send` already use, or no ids to release every finished worker at once, and calls `Queue.Release`: each finished worker is dropped from the queue and its transcript deleted; a worker that is still running is refused (stop it with `cancel` first, do not release a live worker) and an unknown id is refused, each reported per id without stopping the rest, and a transcript that could not be deleted is reported as a warning per id, not a failure. The deletion is the isolation counterpart to session persistence and runs on `release`, on `cancel` (for the worker it kills, once an id has been captured) and on server `close`; a write worker's git worktree is never deleted (the diff and the merge depend on it), only the CLI's session transcript. Safety is the whole point: the per-CLI deletion lives inside each launcher (the same owner split as the launch and the resume), so the queue only asks and never learns where a CLI stores a session; a session id is validated to a plain token (no `/`, `..`, `~`, `*` or any separator) before it is ever put in a path, the CLI's session root is resolved under the user's home and the target is confirmed to stay inside it, a symlink is never followed, and only the exact file is removed (plus, for Claude, the `session-env/<id>` directory the CLI keys by that same id), never a wide glob and never a recursive wipe of a project directory; a missing file is success. The server now lists eleven MCP tools; `diff`, `send`, `steer` and `release` are unit-tested but not yet exercised in a real Claude Code session, and the server instructions, the `doctor` MCP check and the capability registry reflect the count.
- New MCP tool `steer`: it corrects a worker in the middle of a turn without losing its conversation (fourth piece of worker continuation, task T4 of the worker-continuation plan in the internal plans directory), running the correction first instead of waiting for the turn to finish. The spike proved a second message on a live stream is not an interrupt, it is enqueued as the next turn, so there is no native mid-turn steer for the recipes Downshift runs; `steer` is built generically, the same way for every agent, out of two pieces the queue already owns: it stops the live turn with the same kill `cancel` uses but keeps the job and its session, and it puts the correction at the front of the inbox so the resumed session runs it before anything `send` already queued. The interrupted turn settles as a resumable end, not a failure, so the conversation survives; if it had captured no session id yet (killed before its CLI wrote one), the correction is dropped and the worker's delivery says so. On a worker that is not on a live turn, `steer` is a front-of-queue `send`: the correction jumps ahead and runs first. It reuses the worker's own dir, tier, effort and mode, never climbs a tier, and never changes the mode. The reply says `steering` (the correction runs now, position 0) or `queued` with its position when the worker has no turn to interrupt yet. Work the stopped turn had not yet saved to the conversation is lost; writes it already made to its worktree stay, and worktree isolation is unchanged. The Codex CLI also shows a native `turn/steer` in its help, but the spike ran no paid turn against it, so it is left as a future improvement rather than taken without proof. Each queue refusal maps to a clear, task-free message: an unknown id, a worker that cannot be steered (cancelled, failed, or finished with no session to resume), an empty or oversized message, and a full inbox. Steering never blocks `collect`, `cancel` or `status`, and `cancel` still wins after a steer. The server now lists eleven MCP tools; `steer`, `send` and `diff` are unit-tested but not yet exercised in a real Claude Code session, and the server instructions, the `doctor` MCP check and the capability registry reflect the count.
- New MCP tool `send`: it gives an existing worker more work on the same conversation (third piece of worker continuation, task T3 of the worker-continuation plan in the internal plans directory), so a related follow-up reuses the context the worker already built instead of re-reading it. It takes the worker id `collect`, `cancel` and `diff` already use and a task string, and calls `Queue.Continue`: if the worker is still working the task waits and runs as its next turn, and if it has finished the worker is resumed to run it. The reply says whether the task was `queued` behind a running turn, with its 1-based position in that worker's inbox, or `resumed` a finished worker, with position 0 (it runs now, it is not waiting); the state is read from the worker after the turn is accepted, so it stays honest even when a live worker settles between the call and the read. The description tells the orchestrator to use `send` for a related follow-up (shared context) and `delegate` for unrelated work (a fresh worker), speaks only in tiers and never names a model, and states that `send` is not idempotent (each call adds one turn). The result comes back through `collect` like any worker turn. Each queue refusal maps to a clear, task-free message: an unknown id, a worker that cannot take another turn (cancelled, failed, or no captured session to resume), an empty or oversized task, and a full inbox. Enqueuing never blocks `collect`, `cancel` or `status`. The server now lists nine MCP tools; `send` and `diff` are unit-tested but not yet exercised in a real Claude Code session, and the server instructions, the `doctor` MCP check and the capability registry reflect the count.
- The worker queue now holds the state that lets a worker run another turn on the same conversation (second piece of worker continuation, task T2 of the worker-continuation plan in the internal plans directory), without re-paying to re-read its context. It is in-queue state, not a new worker: each job gains an `inbox` of pending turns and a `blocked` state (a worker paused on a question), and `Queue.Continue(id, task)` is the internal "queue one more turn for worker X". A worker still running (or blocked) collects the turn in its inbox and runs it when the current turn settles; a worker that already settled on its own and captured a session id resumes that session at once, and the result comes back through `collect` as a new delivery on the same job id. A resumed turn reuses the original spec with only the task replaced, so it runs in the same directory with the same model, effort and permission mode and never climbs a tier or widens a mode; the queue holds only the opaque session id and task text, and the per-CLI resume recipe stays inside each launcher (a `LaunchResume` built on T1's resume args), so the queue never learns whether the worker is Claude or Codex. The inbox runs one turn at a time in arrival order, and enqueuing during a live turn never blocks `collect`, `cancel` or `status`. Limits mirror `delegate`: at most 8 queued turns per worker and 4,000 bytes per turn; `Continue` refuses an unknown id, a worker that cannot resume (cancelled, failed, or no captured session id), an empty or oversized turn, and a full inbox, each with a clear error and no change to the queue. The `status` worker line gains a `pending` count of queued turns. No MCP tool is wired yet: the `send`, `steer` and `release` tools (tasks T3-T5) build on this base.
- Delegated workers now persist their session so a later turn can resume the same conversation (first piece of worker continuation, task T1 of the worker-continuation plan in the internal plans directory). The launch recipes drop `--no-session-persistence` (Claude) and `--ephemeral` (Codex), and each launcher captures the opaque `session_id` its CLI writes: Claude's `session_id` from the `--output-format json` result object, Codex's `thread_id` from the `thread.started` event of `--json`. The id is surfaced on each `collect` delivery and on the `status` worker line as an optional `session_id`, absent when the CLI wrote none (an older CLI, an error, or a malformed line) so the job still works exactly as before, it is simply not resumable. The resume-and-capture logic lives inside each launcher next to the `report` and `tokens` parsers; the queue stores only the opaque value and never learns which agent produced it (no agent-name `switch` outside the launcher). Each launcher also knows how to build its own resume args (`claude -p --resume <id>` / `codex exec resume <id>`), ready for the tool that calls resume in a later task. Isolation is unchanged: `--strict-mcp-config`, the plan/bypass permission modes, the read-only/workspace-write sandboxes and the worktree-only writes all still apply, and a resume reuses the original spec's model and effort so a continued turn never climbs a tier. A write worker's session is keyed by its own `.downshift/worktrees/<id>` directory, so it does not appear in the user's `/resume` in their own project directory; a read worker runs in the directory the caller named, so its transcript lands in that project's folder (deletion on release is a later task, T5).
- New MCP tool `diff`: it returns the unified diff a write worker has produced in its own git worktree so far, so the orchestrator can review the change without asking the worker to paste code. It takes the worker id `collect` and `cancel` already use and does not block: it reads the worktree as it stands. The diff is the tracked changes against the commit the worktree was created from, then every new file rendered as an addition; it reads the worktree without touching its index (`git diff <base>` for tracked changes, `git ls-files --others` plus `git diff --no-index` per new file), reads only inside that worker's own worktree (never a path from the caller), names binary content instead of dumping it, and is cut at a 48,000-byte cap with the dropped count reported. The result also carries the worker's state. A read-only worker (no worktree) or an unknown id is a clear error; a finished worker still returns its diff while the worktree exists. The tool is marked idempotent like `collect`. The server now lists eight MCP tools, and the server instructions and `doctor` MCP check reflect the count.
- The MCP `status` tool now lists the workers this session has delegated, so the orchestrator can see what is running without calling `collect` and waiting. Each worker reports its id, state (queued, running, done, failed, cancelled or timeout), agent and the harness its strain block names, whether it writes (its own git worktree) or only reads, elapsed time (ticking while it runs, frozen once it ends), the tokens it reported once known, and a short trimmed summary of its result or error. The view lists the active workers plus the most recent finished ones (newest first, capped) and counts any it left out; it never shows a model name, since a job records the agent it ran, not the model. The read is non-blocking (it holds the queue lock only long enough to copy the fields), so a `status` call never serializes behind a waiting `collect` or a `cancel` (spec R22). The quota part of `status` and its result shape are unchanged; the workers section is added, and absent when the server runs no worker queue. `collect` and `cancel` are untouched.
- The exec compactor now compacts the `gh-run` and `gh-pr` families, the two largest GitHub CLI outputs an agent reads: `gh run view --log` (CI logs), `gh run list`, `gh pr view` and `gh pr checks`. `internal/execwrap/expected_format.go` now maps a family to a set of formats, so one family can compact more than one shape. On a real `gh run view --log` sample (2026-10-31, a green CI run), the wrapper cut 378,879 bytes to 3,787 (99.0%) while keeping every job, every annotated error or warning, and every other danger-word line verbatim. A failing run (non-zero exit) still passes through raw and red, and any unparsed danger line keeps the whole log raw, so no failure is ever summarised away.
- `downshift report clear` starts the measurement from zero: it moves every measurement log (routing and child-end events, exec and compaction records, context sensor, loop, DCI and probe logs, and the compressor learning store) to `backups/report-clear-<time>` in the state directory. Nothing is deleted, so a clear is undone by moving the files back. Config, policy, session models, model discovery and quota are kept. It asks first (default No), refuses without a terminal unless `--yes` is passed, and `--dry-run` lists the files and their sizes without moving them.

### Fixed

- The `gh run view --log` summary no longer marks a job failed because a benign danger word appears in its output. Before, any line matching the danger-word pattern (a `warning` in a git hint, a `--warning=no-unknown-keyword` tar flag, a test name containing `fail`) landed in the job's `important` bucket, which both printed it as `ISSUE:` and flipped the job glyph to `✗`, so a green run read as all-failing noise (observed 2026-10-31 on a real green CI run of this repo, run 41202580778: all 6 jobs shown `✗` with 19 bogus `ISSUE:` lines). A job is now marked failed only by a real failure signal: a `##[error]` annotation, a captured test or build failure, or a `Process completed with exit code N` line with N != 0. Benign danger-word lines are still kept verbatim in the summary (the safety invariant is untouched) under an honest `NOTE:` label instead of `ISSUE:`, so after the fix the same run reads 6 jobs `✓`, 0 `ISSUE:`, 19 `NOTE:`. An unparsed danger line still keeps the whole log raw, and a non-zero exit still passes through raw and red.

- Opt-in `downshift exec` shell wrapper (owner decision 2026-10-19; off by default at the time). Superseded before release: the wrapper is now `downshift compact` (`exec` stays an alias), on by default, and needs no Bash allow rule (see Changed). `downshift context enable native --exec` turns it on, `--no-exec` or `downshift context disable` turns it off, and `DOWNSHIFT_EXEC=0` overrides both. When on, the PreToolUse hook rewrites a shell command to `downshift exec -- <command>` only when it is `go test ...` or `git status ...`, every byte is in a small safe set (no pipe, list, redirection, `$`, backtick, parentheses, quotes, globs, braces, tilde, backslash, newline), it is not already wrapped, and the running binary resolves to an executable file (the command invokes it by absolute, symlink-resolved, single-quoted path, never a PATH lookup); anything else runs unchanged. `downshift exec` runs the program with no shell, inherits stdin, forwards SIGINT/SIGTERM/SIGHUP/SIGQUIT, and exits with the program's code (127 when not found, 126 when it cannot run, 128+N on signal N). Output keeps the order the program wrote it in: stdout is held for at most 2 seconds, and only while compaction is still possible; the first stderr byte, 2 MiB or the 2 second bound flushes it and the run stays raw. Stdout is compacted only when the exit code is 0, stderr is empty and the compressor recognises that command's own format, and a compacted result ends with a `[downshift exec: compacted N to M bytes]` marker line. Otherwise it is byte-identical. The child runs in its own process group and a forwarded stop signal reaches the whole group (a SIGKILL of the wrapper itself cannot be forwarded). `DOWNSHIFT_EXEC_DEPTH=1` in the child environment stops nested wrapping. The policy is harness-free (`internal/execwrap`); the hook runner reads `HarnessCapabilities.CanRewriteShellCommand` (true only for Claude Code). The Claude Code adapter only parses `tool_input.command` and emits `updatedInput` with every sibling field kept and no `permissionDecision`, so the harness permission flow still runs on the rewritten command. The hook rewrites only when the user's own Bash allow rule matches the original command and no deny or ask rule in the managed, user, project or local settings does (a settings read or parse error means no rewrite), and `downshift exec` itself refuses anything outside the allowlist with exit 126. No `downshift exec` allow rule is needed or advised. Claude Code needs a manual `Bash` PreToolUse entry (`enable --exec` prints it; `setup` does not write it). Not yet observed on a live session. Telemetry is prompt-free: `exec-events.jsonl` holds the family, raw and emitted bytes, exit class and a compacted flag, never command text, args, paths or output. `downshift context metrics` adds `exec_metrics` with measured bytes saved and `estimated_tokens_saved` (bytes / 4, labelled estimated).

## Development

### Versioning

- **Beta** (v0.1.0-betaX): Router built, adapters tested, harnesses evolving. API may change.
- **Release Candidate** (v0.1.0-rcX): Beta exit criteria met, production-ready.
- **Stable** (v1.0.0+): API stable, harnesses broadly supported, real multi-user evidence.

### Before v1.0.0

Beta exit requires:
1. **Real-spawn verification** (P1): Hook rewrite honored on Claude Code (paid) and Cursor (Pro/Ultra).
2. **Multi-user evidence** (P2): ≥2 external contributors or non-maintainer sessions.
3. **Billing proof** (P3): ≥50 usage events with real provider costs.
4. **Benchmark generalization** (P4): New test set, blind, no tuning leakage.
5. **Harness coverage** (P5): Support matrix up-to-date with no stale TBDs.

See [docs/beta-exit.md](docs/reference/beta-exit.md) for detailed tracking.
