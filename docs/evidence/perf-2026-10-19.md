# Performance evidence — 2026-10-19

Downshift by Tiago Vilas Boas
https://github.com/tiagovilasboas/downshift

What was measured, how, and what was not. No prompts or paths are stored.

## Environment

- Apple M3 Pro, 11 logical CPUs, macOS 26.6.2, Go 1.27.1, arm64.
- `HOME` pointed at an empty temporary directory for every run (no user catalog,
  session file, quota snapshot or event log). Not a quiet machine: other
  agents were running builds, so single runs vary by a few milliseconds.
- Binary built with `go build ./cmd/downshift` (no `-ldflags`, 14 MB).

## Hook cold-process latency

Method: a Python loop spawns the binary, pipes one Claude Code `PreToolUse`
Task payload on stdin, and times spawn to exit with `perf_counter`. 10 warm-up
runs, then n = 150 (before) and n = 200 (after). `version` is the same loop
with no stdin; a no-op Go binary measured the OS floor.

| Case | p50 | p95 | max |
|---|---|---|---|
| no-op Go binary (process floor) | 2.2 ms | 2.7 ms | 3.0 ms |
| `downshift version` (main, after) | 7.7 ms | 10.0 ms | 15.5 ms |
| `downshift claude-code`, Task payload, before | 14.2 ms | 16–19 ms | 36 ms |
| `downshift claude-code`, Task payload, after | 8.5 ms | 9.7 ms | 10.8 ms |

Where the time went (profile of the Task path):

- Two event appends per spawn (`events.jsonl`, `loop-events.jsonl`) each called
  `File.Sync`. On macOS Go implements it as `F_FULLFSYNC`:
  `BenchmarkAppendTo` 2575 µs/op before, 64 µs/op after. This was about 5 ms of
  the ~6 ms removed. PR "drop per-spawn fsync" removed it.
- Package `init` (`GODEBUG=inittrace=1`): `internal/classify` 1.7 ms (it compiles
  the signal and risk regexes eagerly), `codeintel` 0.5 ms, `compressor`
  0.3 ms, `telemetry` 0.2 ms; about 3 ms in total and paid by every command,
  including `version`. Not changed: the hook needs the classify regexes, and
  the only way to remove that cost is precompiled automata.
- Catalog: the 22 KB embedded JSON decodes in well under a millisecond.
- After the change a spawn costs about 0.8 ms more than `version`; the rest is
  process start of a 14 MB binary plus init.

Trade-off: with no fsync, a power loss (not a process crash) can drop the last
telemetry events. The logs are statistics.

Not measured: Linux and Windows; an HDD or network home directory; a populated
`~/.downshift` (large `events.jsonl` rotation, quota snapshot reads); a hook
under heavy parallel spawning. No README text claims microseconds for the hook;
"in milliseconds" is the supported wording.

## Risk scan (`internal/classify`, `go test -bench RiskScan -benchmem`)

| Benchmark | Before | After |
|---|---|---|
| `RiskScanShort` (≈150 chars) | 46 µs | 43 µs |
| `RiskScanBenign1M` | 42 ms | 39 ms |
| `RiskScanWorst1M` | 34 ms | 34 ms |
| `RiskScanAdversarial1M` | 16 ms | 15 ms |
| `RiskScanNoMatch1M` | 753 ms | 238 ms |

The 18× gap between `NoMatch1M` and `Benign1M` is not "an input without a match
is slow". `NoMatch1M` is built so every category's literal prefilter passes
(`xsecretsx`, `tokenz`, `racex`, …) while no word-boundary match exists, so the
four candidate NFA regexes each scan the whole 1 MiB (about 200 ms each; Go's
`regexp` runs a few MB/s per pattern on this input). From 64 KiB the candidate
categories now run concurrently, so the cost is the slowest regex instead of
their sum. The equivalence tests (`TestRiskScanEquivalence*`) pass unchanged.
A single-core run, or a hook limited to one CPU, would not see the speed-up.
`RiskRef*` (the reference scan) was left alone.

The earlier aggregate run printed none of the `core` and `compressor`
benchmarks (cause not established); run the packages explicitly:

```bash
HOME="$(mktemp -d)" go test -run '^$' -bench . -benchmem \
  ./internal/core ./internal/compressor ./internal/codeintel
```

`ClassifyTypical` is 313 µs for one typical prompt: negligible beside the 7–8 ms
process cost, so it was not optimised.

## DCI (repository-level), from the earlier run

Cold index 582 ms, warm path p95 5.2 ms; the context benchmark's byte savings
(for example `go test all-ok` 75 → 30 bytes) are bytes only, not tokens or money.
These were not re-run here.

## Not measured

Token or dollar savings, routing accuracy, and end-to-end harness latency (the
harness spawn, the model call). Do not quote a saving percentage from this file.
