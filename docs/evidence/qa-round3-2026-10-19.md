## 2. Fail-open black box, all six hosts

Harness: a throwaway Python `subprocess` script (not committed) against a
freshly built binary. One fresh `HOME`, event log and `DOWNSHIFT_CONTROL_SHARE=0`
per case, cwd outside the repo. Payloads: `{not json`, empty stdin, `[]`, wrong
types (`{"tool_name":5,"tool_input":"x","toolCall":7,"v":"a","model":[1]}`), a
1 MiB + 10 byte prompt, the two example Task payloads from `examples/`, and a
stdin that receives a truncated JSON prefix and is never closed. n = 6 hosts x
8 cases = 48 runs, plus 6 never-closing runs measured separately (the first
attempt of that case closed stdin by mistake and was discarded).

All 54 runs exited 0 and none timed out. Never-closing stdin ended at 2.03-2.05 s
on all six hosts (cap 2 s). Stdout is unchanged from the previous round:

| Host | Neutral or fail-open answer | Real rewrite |
|---|---|---|
| claude-code | `{}` | allow + `updatedInput` (`model: haiku`), 0.01 s |
| codex | `{}` | not produced by the example payload (no session list on that host); `{}` |
| cursor | `{"permission":"allow"}` | `updated_input` + `agent_message` with a session list in the payload |
| antigravity | `{"decision":"allow"}` | `{"decision":"allow"}` (no rewrite from the example) |
| kirocrew | empty stdout | exit 2 with the respawn message on stderr (the policy contract, designed) |
| opencode | `{"v":1,"action":"allow","reasonCode":"fail_open"}` | same (example is not an opencode wire payload) |

Result: exit codes and the neutral contract are unchanged by #211-#218. The
`harness-matrix.md` section "Answer when nothing is rewritten" matches the
binary for all five rows. Limit: real rewrites were only reproduced for
claude-code, cursor and kirocrew; codex, antigravity and opencode were not
driven with a host-native rewrite payload.

## 3. New pieces

### 3.1 Price sync (`scripts/sync_catalog_prices.py`, #213)

Method: a copy of the script and `catalog.json` under a temp directory, a mocked
`--snapshot` for `claude-opus-5-5` (catalog: input 4.0, output 20.0 USD per 1M),
checksum of the copy compared before and after each case, the repository's
`catalog.json` checksum compared at the end (`6e167ca68314`, unchanged).

| Source price | Exit | Catalog changed | Message |
|---|---|---|---|
| negative `-0.000004` | 1 | no | "must be greater than zero" |
| `NaN`, `Infinity` | 1 | no | "not finite" |
| 1000x (`0.004`/`0.02`) | 1 | no | "exceeds the 1000 limit" |
| 1000x with `--allow-large-change` | 1 | no | still rejected by the absolute limit |
| string `abc` | 1 | no | "not a number" |
| list `[1]` | 1 | no | "not a number" |
| JSON `true` | 1 | no | rejected as 1000000 USD (accepted as the number 1, misleading text) |
| numeric `0` | 1 | no | "must be greater than zero" |
| string `""` or `"0"` | 0 | no | skipped silently as "no price" (0 changes) |
| `null` prompt | 1 | no | "source has no priced models" |
| legitimate 4x (`0.000016`/`0.00008`) | 0 | yes | 4.00 -> 16.00, 20.00 -> 80.00 |
| 6x without the flag | 1 | no | "6x move (limit 5x)" |
| exactly 5x down (to 0.80) | 0 | dry-run | accepted (limit is exclusive of 5x) |
| 5% move | 0 | yes | 4.00 -> 4.20 |
| `--dry-run` with a move | 0 | no | changes printed only |
| malformed JSON, missing file | 1 | no | |

PASS: invalid prices never reach the catalog and a legitimate 4x move is
accepted. Residual items (P2): the string forms `""` and `"0"` are skipped
while a numeric `0` is rejected (inconsistent, harmless); a key that is absent
from the catalog gets only the absolute 1000 USD cap, not the 5x check; a
boolean is read as a number. The workflow `sync-prices.yml` has still never
run (first schedule: Monday 06:17 UTC), so the end-to-end path (force push of
`chore/sync-prices`, PR creation, `actions: write` dispatch) is not exercised.
