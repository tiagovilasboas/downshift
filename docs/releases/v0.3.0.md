# Release v0.3.0

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift](https://github.com/tiagovilasboas/downshift). In this release the orchestrator LLM chooses the model and Downshift applies, compacts and measures it. Downshift's own code calls no LLM. This is v0.3.0, the release after v0.2.0.

## What changed for you

### The orchestrator chooses the model, Downshift applies it (decision O8)

Downshift no longer picks a model on its own. The decider runs in order, first match wins:

1. a pinned model is kept;
2. then a declared profile;
3. then the first matching declared rule;
4. then the orchestrator's tier hint (it can only move down for now);
5. otherwise the requested model is kept.

The old built-in agent-type table and the automatic upgrade after a failure are gone. Without a policy and without a hint, nothing changes. To get similar behaviour, declare profiles in `.downshift/policy.json` (`downshift policy init` previews a starting file and writes it only after a yes), or let the orchestrator put `[tier=small]` at the start of the spawn prompt. The `downshift-orchestrator` skill, installed by `setup`, carries the guidance. The guard still refuses foreign ids and explicit-only models and keeps the requested model on doubt. The built-in risk veto is gone: protection is now the orchestrator's judgment plus the tier floors you declare in `policy.json`.

### A new MCP server

`downshift mcp serve` is an MCP server on stdio, built on the official Go SDK. It has four read and information tools: `providers`, `playbook`, `status` and `apply`. It never picks a model and takes no task text.

It also has `delegate`, `collect` and `cancel` for read-only workers (queue limit four). Read and write worker launches are opt-in, and some paths have not yet run against the real CLI, so treat the worker launches as experimental.

### setup registers the MCP server across harnesses

By default `downshift setup` registers the `downshift` server in:

- Claude Code, through `claude mcp add -s user`;
- Codex, as a marked block in `config.toml`;
- Cursor, Antigravity, KiroCrew/Kiro and Claude Desktop Chat, declaratively (a JSON merge that touches only the `downshift` member and leaves other servers byte-for-byte).

`--no-mcp` skips it, the dry run shows it first, and `setup --undo` removes it. For Claude Desktop Chat, restart Claude Desktop to pick the server up; only the read and apply tools work from Chat.

### doctor declares what each surface cannot run

`downshift doctor` now states the limits per harness. Claude Desktop Chat spawns no model-carrying subagent and has no shell tool, so model rewrite, compaction and mid-session routing are reported as none; its read-only MCP tools still answer. Claude Desktop Cowork runs in a Linux VM the host never reaches, so every hook-driven feature is none and MCP is unverified. The Claude Desktop Code tab is the normal claude-code harness and is unchanged.

### The `client` field on events

Routing events and exec (compaction) events now carry an optional `client` field naming which Claude Code client fired the hook. It is read from `CLAUDE_CODE_ENTRYPOINT` (values seen include `cli` and `claude-desktop`), sanitized, never used for policy, and absent on older events or on harnesses that do not report it.

### A routing circuit breaker

After three identical hook failures for a harness, routing stops for it: spawns pass unchanged, and `doctor` fails with one line per open circuit. A routed decision closes the circuit, and the hook routes once as a probe five minutes after the last failure.

### Smaller changes you may notice

- On Claude Code, the small target is now the newest Haiku, `claude-haiku-5-5`, written as the native `haiku` alias (observed 2026-10-28; previously `claude-haiku-4-5`). The quality comparison against the old target has not been run, so treat the change as unproven on quality.
- `setup` no longer writes `session-models.json`. Models are the ones the harness reports; the file is an optional manual override. When a harness has no detected list, `setup` names `downshift models discover`.
- Reports show tokens per harness (dollar accounting was rejected). `downshift report` shows why spawns changed or stayed; `downshift session --panel` shows requested model, final model, verdict and reason per spawn.
- State directory default is `~/.downshift`, with `~/.harness-downshift` as a legacy fallback. There is no automatic data migration; `doctor` reports a legacy directory when it finds one.

## What breaks

- `downshift try` is removed. Inspect decisions with `downshift session --why` or `downshift stats`.
- `DOWNSHIFT_NB_*` environment variables are no longer read.
- All mods are removed (owner decision, 2026-10-29): savvy-progress, cache-tax, downshift-progress, downshift-panel, downshift-dock, downshift-router, downshift-theme and downshift-opencode. `downshift setup` no longer installs any mod. Remove an installed mod with `/plugin uninstall <name>@downshift`. The marketplace now offers the `downshift` plugin only.
- `downshift dashboard` and `downshift serve` are removed (owner decision N9). For the same data in the terminal, use `downshift session --tree`, `downshift watch` and `downshift report`. If the `dsmon-server` launch agent was installed (it ran `serve`), stop it with:

  ```bash
  launchctl bootout gui/$(id -u)/com.tiagovilasboas.dsmon-server
  ```

- The default routing behaviour changed: the old built-in agent-type table and the automatic upgrade after a failure are gone (see decision O8 above).
- `downshift setup` no longer writes `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`. With it on, Claude Code forces one model on every subagent and ignores both the per-call model and a Downshift rewrite (observed on Claude Code 2.1.310, 2026-10-29). A value you set yourself is left alone, but `downshift doctor` now fails when `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` is on, whether in the harness settings env block or the environment.

## Migration checklist

1. Install v0.3.0:

   ```bash
   go install github.com/tiagovilasboas/downshift/cmd/downshift@v0.3.0
   ```

   or the one-liner:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/tiagovilasboas/downshift/main/install.sh | sh
   ```

2. Run setup and review the diff. It now also registers the MCP server; add `--no-mcp` to skip that:

   ```bash
   downshift setup
   ```

3. Uninstall any mod you still have (repeat per mod):

   ```bash
   /plugin uninstall <name>@downshift
   ```

4. Stop the `dsmon-server` launch agent if it was installed:

   ```bash
   launchctl bootout gui/$(id -u)/com.tiagovilasboas.dsmon-server
   ```

5. Unset `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` if you set it, so doctor passes and subagent routing works:

   ```bash
   unset CLAUDE_CODE_SUBAGENT_MODEL_FORCE
   ```

6. Confirm the install:

   ```bash
   downshift doctor
   ```

## Roll back

Install v0.2.0 and undo the setup changes, which restores the hook files and removes the MCP registration:

```bash
go install github.com/tiagovilasboas/downshift/cmd/downshift@v0.2.0
downshift setup --undo
```

The named rollback path is to revert the upgrade commit. To remove hooks and state entirely:

```bash
downshift uninstall --purge
```
