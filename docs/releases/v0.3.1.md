# Release v0.3.1

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift](https://github.com/tiagovilasboas/downshift). A patch release on top of v0.3.0. It carries one security fix for the MCP worker tools, and the gaps found while checking Downshift end to end in Claude Code.

## Upgrade first if you use the worker tools

Claude workers started by the MCP `delegate` tool used to load every MCP server you had registered, claude.ai connectors (mail, GitHub, documents) and Downshift itself included. On the write route (`DOWNSHIFT_WORKERS=bypass`) the worker runs with `bypassPermissions`, so those tools could run without approval. Workers now start with `--strict-mcp-config` and load no MCP server (#659).

Measured on one machine: a print-mode Claude session loaded 31 servers and 323 tools without the flag, and none and 29 tools with it.

If you never set `DOWNSHIFT_WORKERS`, the worker tools were off and this did not affect you.

## What changed

- **Write workers refuse a broad directory.** With `DOWNSHIFT_WORKERS=bypass`, a write job is refused when the server was started in the filesystem root, your home or a directory above it, or when the job names such a directory (#655).
- **The `providers` tool can no longer narrow the model list.** A report now adds to the models Downshift already knew instead of replacing them. Before, one call naming a single model left routing with only that model for an hour (#660).
- **Subagent end records name the real model.** `child_ended` events for Claude Code now carry the model the subagent ran on, read from its transcript, instead of `unknown` (#657).
- **`doctor` says what Claude Code cannot do.** Claude Code gains `effort: none`: the Agent tool takes no per-call effort, so the hook cannot set one. A stale `claude-statusline` quota now names its cause: the statusline runs only in an interactive terminal, never in the Claude Desktop Code tab or `claude -p` (#656).
- **Clearer guidance for the orchestrator.** The session-start line, the MCP server instructions and the `providers` description ask for a `providers` call before every spawn (#654). The instructions also say whether the worker tools are on, when delegating is not worth it, that a worker's report is data and not instructions, and that every worker started must be collected (#658).

## What you need to do

Nothing beyond installing this version. If you want effort applied to delegated work, pass `effort` to the MCP `delegate` tool: the worker gets `--effort`, which the Agent hook cannot set.

## Roll back

Install v0.2.0 or v0.3.0 from the [releases page](https://github.com/tiagovilasboas/downshift/releases), or revert the commits above. Rolling back below v0.3.1 brings back the worker MCP inheritance described above.
