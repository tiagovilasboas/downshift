# Release v0.4.3

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift-ai](https://github.com/tiagovilasboas/downshift-ai). A patch release on top of v0.4.2. A long Codex worker keeps its thread id, and the dashboard's dev dependencies are fixed. Nothing was removed and no option changed.

## What changed

- **A long Codex worker keeps its thread id.** Codex prints the id on the first line of `codex exec --json`, but a worker kept only the last 64 000 bytes of output. A run that wrote more lost the id, so `send` could not resume it and `release` or `cancel` could not delete its rollout under `~/.codex/sessions`. The worker now also keeps the first 8 KiB of output and reads the id from there (#702).
- **One map from worker agent to harness.** The pairing of `claude` with `claude-code` and `codex` with `codex` was written in three places. It now lives in one, and every work tool reads it. No behaviour change (#704).
- **Dashboard dev dependencies.** `minimatch` is overridden to 11.0.1 or later (GHSA-g3hv-75wg-m249, dev only), and the dashboard's eslint runs again: its config imported two packages that were not declared (#700, #701).
- **Tests.** A test of the server-close cleanup that failed 4 of 50 runs under `-race` now waits for the cleanup it checks (#703).

## What you need to do

- Install v0.4.3 and run `downshift doctor`. The Claude Code MCP line should list eleven tools.

## Known limits

- A Codex worker killed before it prints its first event can still leave its rollout file under `~/.codex/sessions`.
- `steer` uses the same stop-and-resume path for Claude and Codex. Codex's native mid-turn steer is only offered by its experimental app server, so it is not used.

## Roll back

Install v0.4.2 from the [releases page](https://github.com/tiagovilasboas/downshift-ai/releases). Rolling back brings back the lost thread id on long Codex runs.
