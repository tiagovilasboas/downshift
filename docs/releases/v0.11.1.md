# Release v0.11.1 (public beta)

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift-ai](https://github.com/tiagovilasboas/downshift-ai).

Downshift cuts the tokens an AI coding agent spends: it compacts verbose command output before it reaches the context, applies the orchestrator's model choice to each subagent within your policy, and measures both. Its own code never calls an LLM, and every hook fails open. [CHANGELOG](../../CHANGELOG.md#0111---2026-11-07) lists every change.

## What changed

- **`downshift policy init` proposes the `explore` profile.** `downshift policy init` (and `downshift setup`, unless `--no-policy`) now proposes one `explore` profile per harness whose hook can rewrite a subagent's model and whose model list is known. The agent type of that name (such as Claude Code's `Explore`) runs on the small tier. The plan notes the model each profile resolves to today and its source; a harness with no detected list gets a note naming `downshift models discover` and no profile. `--bare` writes the version only. Nothing is written before user confirmation (`--yes`), and the profile is declared policy that can be modified or deleted.
- **Deduplicated doctor hook overlap warnings.** `downshift doctor` now reports one clean `hook overlap` warning per rival rewriter instead of duplicate conflict notices. With the compact wrapper off (`"exec": false` or `DOWNSHIFT_EXEC=0`), a shell rewriter beside Downshift is no longer reported as an overlap since Downshift rewrites no command; a model rewriter still is.

## What you need to do

1. Install or update to v0.11.1 (`install.sh` or the [release assets](https://github.com/tiagovilasboas/downshift-ai/releases)).
2. Run `downshift doctor` and review your environment status.
3. Open a new harness session and verify metrics with `downshift session`.
