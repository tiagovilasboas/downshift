# Release v0.4.0

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift](https://github.com/tiagovilasboas/downshift). A minor release on top of v0.3.1. Downshift is simpler: the orchestrator picks the model, Downshift applies that choice by tier only and never on price, and the MCP server can now keep a worker's conversation going instead of starting over. Some options were removed, so read "Breaking" before you upgrade.

## Breaking

- **Downshift never raises a model on its own.** The legacy opt-in upshift is gone: `DOWNSHIFT_EXPLICIT_UPSHIFT`, `DOWNSHIFT_NB_UPSHIFT`, the `explicit_upshift` key in `session-models.json` and the installer flag `--explicit-upshift`, which `install.sh` now refuses. A model marked `explicit_only` is never picked by routing in either direction. The only lift left is a tier floor you declare in `.downshift/policy.json` (#677, #678, #679, #680).
- **No prices anywhere.** Routing decides by tier only: a downshift needs a strictly lower tier, and models of the same tier keep the session's order. The catalog no longer carries prices, `doctor` no longer checks them, `dsmon` shows `↓` instead of a percentage, and `report` counts a task by observed token usage (#669, #670, #671, #674). A catalog override written for an older version still loads; its price keys are ignored.
- **Event format.** `events.jsonl` no longer writes `estimated_savings`, `gateway_price` or `upshift_cost_ratio`. Older lines that carry them are still read (#676).
- **Skill renamed.** `cost-reducer` is now `downshift-tune`. The Claude Code plugin picks up the new name on update; a copy you made by hand can be deleted (#675).

## What changed

- **Seven worker tools in the MCP server, eleven tools in all.** Besides `delegate`, `collect` and `cancel`:
  - `diff` returns what a write worker changed in its worktree, so you review the change instead of asking the worker to paste code (#682).
  - `status` lists this session's workers: state, mode, elapsed time, tokens and a short result (#684).
  - `send` gives a worker a related follow-up on the same conversation, so it does not read everything again. In a spike, the second turn sent 2 new input tokens and read the rest from cache (#685, #686, #687).
  - `steer` corrects a worker in the middle of a turn: it stops the turn and resumes the same conversation with your correction first. Work the stopped turn had not saved is lost; files already in its worktree stay (#689).
  - `release` lets finished workers go and deletes the session transcript they left on disk. It also runs on `cancel` and when the server closes. Claude workers get their session id before they start, so a cancel in the first turn cleans up too (#690, #692).
  A worker keeps the tier, effort, directory and mode it started with on every turn.
- **Compactor covers `gh run` and `gh pr`.** One real `gh run view --log` went from 378,879 to 3,787 bytes (#665). The summary only marks a job failed on a real failure signal, not on a benign "warning" or "error" in a passing run (#666).
- **Clearer tier guidance for the orchestrator.** The session-start line, the MCP instructions and the orchestrator skill say what counts as mechanical work, that `[tier=small]` only moves down, and that the choice is by tier, never by model name (#673).
- **`downshift report clear`** moves the measurement files to a dated backup so a comparison starts from zero (#663).
- **Faster CI.** The required gate went from about 162 s to about 103 s (#664).

## What you need to do

- Remove `--explicit-upshift` from any install script, and `explicit_upshift` from `session-models.json` if you set it.
- If you read `events.jsonl` with your own tools, stop reading the three removed fields.
- Run `downshift doctor` after installing. The Claude Code MCP line should list eleven tools.

## Known limits

- A Codex worker gets its session id only after its first turn ends, so a cancel during that turn can leave its rollout file under `~/.codex/sessions`.
- `steer` uses the same stop-and-resume path for Claude and Codex; Codex's native mid-turn steer is not used yet.

## Roll back

Install v0.3.1 from the [releases page](https://github.com/tiagovilasboas/downshift/releases). Rolling back brings back the removed options above and loses the new worker tools; a v0.3.1 worker keeps no session, so there is nothing to clean up.
