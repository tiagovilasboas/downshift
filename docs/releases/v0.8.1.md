# Release v0.8.1

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift-ai](https://github.com/tiagovilasboas/downshift-ai).

This is a patch release. It fixes what a security review of the v0.8.0 workers and the OpenCode bridge found, plus the minor findings of the code reviews that followed. There is no new default. Read workers now need a recent Claude CLI (see below). [CHANGELOG](../../CHANGELOG.md#081---2026-11-05) lists every change.

## What changed

- **Workers are isolated from the repository they run in.** A Claude worker loads only your user settings (`--setting-sources user`), so a `.claude/settings.json` in a repository can no longer run hooks or widen permissions in a worker. A read worker gets only `Read`, `Grep` and `Glob`. Workers inherit a filtered environment: unrelated tokens (GitHub, npm, cloud, database) stay out. `DOWNSHIFT_WORKER_ENV` passes extra variables you name.
- **Worker limits hold for follow-up turns.** `send` and `steer` wait for a free slot, check the token budget, and count toward a per-session turn cap.
- **A broken worker policy file turns workers off** instead of falling back to the next layer.
- **Read workers under a broad MCP root.** When the server starts in your home or the filesystem root, a read worker's directory is refused when it is broad itself or sits below a hidden directory such as `~/.ssh`.
- **MCP tool annotations.** `delegate`, `send` and `steer` say they are destructive and open-world, so a client does not auto-approve them as harmless.
- **Setup does not write through links.** A harness file that is a link, or sits in a linked directory (for example `~/.config/opencode` in a dotfiles repository), is refused and left alone. Windows junctions count. `setup --undo` follows the same rule. When one file of a harness is refused, setup changes nothing else of that harness, so it is never half installed. Since 0.8.0 setup followed such links.
- **OpenCode bridge.** The shell guard reads every config source OpenCode reads, in the shell's and the session's directory and their ancestors, and keeps the compactor off on any doubt. A shell rewrite is applied only with Downshift's wrapper in command position, from the `downshift` binary the bridge pinned at startup. Retry calls are validated. Session models with a slash in the id are routed. Pending shell session tags expire and are capped.
- **Fixes.** A resumed Codex worker returns its final message, not the raw event stream. A commented `opencode.jsonc` gets a manual hint. On Windows a worker starts suspended and joins its Job Object before it runs.

## What you need to do

1. Install v0.8.1.
2. Read workers need a Claude CLI that knows `--setting-sources`, `--tools` and `--permission-prompts`. Update Claude Code if a read worker fails to start.
3. If a worker needs a variable from your shell that it no longer gets (for example a Codex provider's `env_key`), add its name to `DOWNSHIFT_WORKER_ENV`, comma- or space-separated.
4. Run `downshift setup --yes`. If setup reports a linked file or directory, edit the real file by hand or remove the link.
5. On OpenCode, run `downshift setup opencode` to install the new bridge files.
6. Open a new harness session.
