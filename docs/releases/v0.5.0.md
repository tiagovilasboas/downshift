# Release v0.5.0

Downshift by Tiago Vilas Boas: [github.com/tiagovilasboas/downshift](https://github.com/tiagovilasboas/downshift). A minor release on top of v0.4.3. Routing now decides by task class, every spawn is routed, the Compactor handles failing runs, and the agent orchestration lands. Several unused features are removed. Read "What you need to do" before upgrading.

## What changed

- **Routing decides by task class, on by default (#734).** When no pin, profile, rule or tier hint decided a spawn, a decisive `TRIVIAL` or `SIMPLE` task with no risk category moves down to the small tier. `MEDIUM` and `COMPLEX` never move down. `routing.by_class: false` in `policy.json` turns it off.
- **Two safety rules and an opt-in raise (#735).** After a downshift that ended in error or was interrupted, the next spawn of that session is not moved down for 10 minutes. When the orchestrator asks for the small tier on a decisive `COMPLEX` task, the spawn runs as asked and Claude Code gets a note suggesting the mid tier. `routing.raise_complex: true` (off by default) moves that spawn up to mid, never higher.
- **Every spawn is routed (#757).** The control group, `DOWNSHIFT_CONTROL_SHARE` and `DOWNSHIFT_NO_ROUTE` are removed. Only `downshift session --pause` leaves spawns unrouted, on request.
- **`downshift report` leads with compaction savings per harness, in tokens (#718).** It then shows routed tokens per completed task and rework per routing verdict (a verdict is flagged at 20 completed tasks). It counts billable tokens, and the rework link no longer crosses groups.
- **The Compactor handles more.** Failing vitest (3, 4, 5) and playwright runs are compacted without losing a failure (#738). Clean `go test` runs fold inside `make`, `git commit` and `git push`. Real vitest 3, 4 and 5 output and coloured output compact. A `go test` that prints a note on stderr compacts.
- **The guards fail closed.** `psql`, `gcloud` and `ast-grep` accept only the read shapes they can prove, `redis-cli` and `valkey-cli` accept a closed flag list, a recursive `rm` is refused in every spelling, and guarded commands are not wrapped behind a runner or inside a chain.
- **`downshift export` (#719).** One JSON file with counts and token totals, checked against an allowlist before it prints, for an operator who shares one measurement week. The operator guide is `docs/guides/operator.md`.
- **Agent orchestration (#758, #759, #764, #765).** A roster of programming agents, the `downshift-squad` skill, implicit routing without a `squad` prefix, and the context-triggered commands `downshift full-force` and `downshift shift <squad>`.
- **The `downshift-agents` mod (#770, #773).** A Claude Code mod with a band above the prompt and a `/ds-agents` pane: task progress, the live subagent list, Compactor figures and routing decisions. It only observes. `downshift setup` installs it with the Claude Code plugin; `--no-mods` skips it. The band no longer draws a rounded frame, so its row keeps its columns (#773), and its logo is drawn bare and theme-aware at 24 px (#775).
- **`downshift setup` installs the `ponytail` skill (#772)** with the other Downshift skills.
- **`downshift doctor`** calls the read-only `playbook` MCP tool and checks the hooks of the installed Claude Code plugin against this binary.
- **Output names tiers, not prices.** The live views and reports no longer show tokens on a lower tier as "saved" or "cheaper".

## What was removed

- Code intelligence (DCI): the `downshift dci` commands, its hook, `stats --dci` and the report section. `downshift dci hook <harness>` still exits 0 with no output, so a harness set up by an older version keeps working; `downshift setup` removes the retired hook entry.
- Economy mode: `downshift policy economy` prints a removal notice and exits 1. A `"mode"` key already in `policy.json` is accepted and ignored.
- The web dashboard code and its HTTP API, the naive-Bayes TRIVIAL downshift opinion, the legacy accounting aggregations, and about 30 functions that only tests reached.

## What you need to do

- Install v0.5.0 and run `downshift doctor`. The Claude Code MCP line should list eleven tools, and the `plugin hooks` row should be OK.
- If a script sets `DOWNSHIFT_NO_ROUTE` or `DOWNSHIFT_CONTROL_SHARE`, remove it: neither has any effect now. To leave spawns unrouted for one session, use `downshift session --pause`.
- If you ran `downshift dci` or `downshift policy economy`, stop: both are gone.
- Run `downshift setup --dry-run` and read the diff. It removes the retired DCI hook entry and adds the `downshift-agents` mod and the `ponytail` skill.

## Known limits

- The class step is made of patterns, not a proof, and it only moves simple work down. Downshift has no built-in risk floor since 2026-10-28; declare a tier floor in `.downshift/policy.json` for a hard guarantee.
- A decisive `COMPLEX` call is labelled `COMPLEX` in 92% to 100% of cases on four eval sets and 61% (11 of 18) on one blind set, so `routing.raise_complex` stays off by default.
- Model rewrite is observed honored on Claude Code only. Codex is inferred, Cursor is unconfirmed, KiroCrew has no rewrite channel.
- The control arm of the earlier trials no longer exists, so the first routed-versus-control comparison cannot be repeated. Those studies are kept as dated history.

## Roll back

Install v0.4.3 from the [releases page](https://github.com/tiagovilasboas/downshift/releases). Rolling back brings back `DOWNSHIFT_NO_ROUTE` and the control group, and `downshift dci`.
