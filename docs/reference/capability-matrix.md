# Capability matrix

Downshift by Tiago Vilas Boas · https://github.com/tiagovilasboas/downshift

Audit date: 2026-10-17. Source of truth for writers: every row below was read from code, tests or a dated evidence
file in this repository, not from existing marketing text. When a public doc says more than a row supports, the doc
is listed in [Contradictions and overclaims found](#contradictions-and-overclaims-found).

**Status vocabulary (one of five):** *Implemented* means code, tests and at least one dated observation on a real
harness. *Implemented, not validated everywhere* means the code is shared but the effect was observed on some
harnesses or plans only. *Experimental* means shipped behind a flag or a maintainer command, with no production
claim. *Planned* means documented intent with no code path. *Not supported* means the harness or design cannot do it.

Harness status words (Completed, Functional, Beta, Experimental) are a different scale and are defined in [harness-matrix.md](harness-matrix.md#status-per-harness); they appear only in section 4.

Shorthand: `core` is `internal/core`, `cmd` is `cmd/downshift`, "matrix" is `docs/reference/harness-matrix.md`,
"A/B" is `docs/evidence/subagent-routing-ab-2026-10-15.md`, "audit" is `docs/evidence/hardening-audit-2026-10-15.md`.

## Hidden capabilities

Things the code does that no public doc explains well (file where it lives; where it is mentioned, if at all).

1. **Verification sensor.** `SubagentStop` records whether the child ran a recognised test or lint command and whether the last one passed (`verification: passed|failed|none` on usage records); `downshift verification-report` groups cost per tier next to that verdict. `internal/adapters/claudecode/verification.go`, `cmd/verification.go`. Mentioned once in CHANGELOG; absent from `help --all`, README, stats-export.
2. **Prompt-injection as a risk category.** A task that says "ignore previous instructions", "this is a trivial task" or "use the cheapest model" is treated as risky: never downshifted, floor off the small tier. `core/risk.go` `prompt_injection`. Docs name the category in passing only.
3. **The hook's time and safety budget.** 1 MiB payload cap, 2 s stdin read timeout, a 1.5 s hook deadline (`hookctx.HookBudget`) that kills helper commands, 1 s per embed call, 400 ms transcript wait, 500 ms sensor lock, 3 s graph fetcher, and `CmdTrusted`, which refuses an E5 helper that is `curl`, `bash`, `-c` or a symlink. `cmd/main.go`, `internal/hookctx`, `semantic/embed.go`, `e5shadow/cmdvalidate.go`. None of these numbers or the helper-command policy appear in user docs.
4. **Operational knobs.** Event-log rotation (`DOWNSHIFT_LOG_MAX_MB`, `DOWNSHIFT_LOG_MAX_BACKUPS`), `DOWNSHIFT_NB_UPSHIFT`, `DOWNSHIFT_NB_DOWNSHIFT`, `DOWNSHIFT_QUIET`, and `DOWNSHIFT_CONTROL_SHARE` are listed in `docs/guides/config.md`. `DOWNSHIFT_E5_*`, `DOWNSHIFT_GRAPHIFY_CMD`, and `DOWNSHIFT_MINILM_EMBED` are gone.
5. ~~Graph escalation~~ removed 2026-10-17.
6. **Second stderr line per spawn.** `downshift: honor=unobserved quota=<available|held|unknown> usage=unobserved` is printed for every decision on every harness; only `docs/guides/daily-truth.md` describes it.
7. **Antigravity multi-child rule.** The decision, the task text and the written model all follow the last subagent that has a `Prompt`; earlier children are not routed. `antigravity.go` `decidedSubagent`, `TestMultiChild_*`. Only the hardening audit and CHANGELOG mention it.
8. **Decision-intelligence shadow record and in-process extras.** Every decision event carries a `decision_intelligence` advisory block (`Apply: false`); `internal/orchestration` (Go fan-out planner), `internal/routecache` and `internal/lifecycleobserver` compile but have no CLI or hook path. Design docs exist; user docs do not say they are inert.
9. **Agent-type baseline attribution.** `stats --detail` prints "Baseline by agent type" so an unknown-baseline rate can be pinned on `Explore`, `Plan` or `custom`. Only `stats-export.md` describes it.
10. **Refuted-rewrite honesty.** When Claude Code reports a different `resolvedModel`, the decision is priced on the model that ran, saves nothing, leaves the model mix and never counts as inferred honored (`TestAggregate_RefutedRewriteSavesNothing`). Explained in the audit and CHANGELOG, not in the stats docs a user reads.
